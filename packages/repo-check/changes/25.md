The check now refuses the flags, settings and commands that npm reads ahead of a project's `.npmrc`,
and the two installs no project setting reaches, and it fails on an npm too old to read
`allow-git` and `allow-remote`.

- **Rules.** The `--allow-git` and `--allow-remote` flags, and the `npm_config_allow_git` and
  `npm_config_allow_remote` settings, given anything but `none` are refused in any text file but a
  doc or a test, as the install scripts flag and setting already are. A setting is read after a
  quote and a closing bracket, as code writes a key, and past the rest of a comparison such as
  `===`. npm's config command writing one of the three settings to the project's `.npmrc`, or
  editing it, is refused. An install into npm's global folder without the flag that turns install
  scripts off is refused, as one pointed at another folder already is. npx, and npm's `exec`
  command and its alias, are refused unless their own options end with `--no-install` or `--no`,
  and npm's `create` command, and its `init` command given an initializer, are refused, each read
  where it starts a command. Every Dockerfile stage now holds all three settings before its first
  RUN, each set with ENV or the `.npmrc` copied in by name.
- **Command.** `check-installs` fails when the npm on the path is older than 11.14.0.
- **Function.** `npmFloorProblems` is exported with its types.
- **Docs.** The README says what each new rule refuses and why, and no longer says that no command
  is read.
- **Tests.** Each new form is refused through the rules alone, and the npm floor and a workflow
  that fetches are refused through the command, with a stand-in npm on the path for the floor.
