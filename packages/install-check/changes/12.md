The first version: a `check-installs` command that fails a build on an npm install that runs its packages' install scripts, in a repository's workflows, composite actions and Dockerfiles.

- **Readers.** A workflow or composite action is read as each step's `run`, a block, a folded block or one quoted value, with the line of its `run` and the folder its `working-directory` names, and none of its other keys, a comment left out of the key's own line only outside quotes. A Dockerfile is read as each `RUN` behind any BuildKit flags, in shell form, exec form or with a heredoc whose own line is read as well as its body, continued lines joined past comment lines. In a script, a command is found wherever it sits, inside parentheses, a substitution, a process substitution or another shell, with quotes read in one pass as bash reads them, a `#` that starts a word opening a comment, a flag that takes a value passed over with its value, and a redirection left out. npm's install commands in every spelling, npx, `npm exec` and `npm x` without `--no-install` among their own options, and `npm init` or `npm create` given an initializer each count as an install, with scripts off where the last of the command's own flags that names them says so.
- **Command.** `check-installs` reads every workflow, composite action and Dockerfile git tracks or would add, names each install that leaves scripts on by its file and line with the command beneath, and exits 0 on a pass, 1 on a refusal and 2 with how to run it when given an argument or run outside a git repository.
- **Function.** `installProblems`, `runsOf`, `dockerRunsOf`, `npmCommandsIn`, `installs` and `skipsScripts` are exported with their types.
- **Docs.** The README says what counts as an install, what the check reads and how it reads a script, how to run it, and what a failure looks like.
- **Tests.** Every case the copies of this reader in the house's repositories held passes, with the cases they read differently settled as bash runs them, and the command is run against throwaway repositories for a pass, a refusal in a workflow, a composite action and a Dockerfile, and bad usage.
