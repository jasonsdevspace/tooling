A `check-commit-message` command holds a commit message, or a pull request's title and body, to
every prose rule and refuses one that names a tool, in a minor version, since it adds a command and
changes nothing a repository runs today.

- **Command.** `check-commit-message` takes the path to a message file and reads only what git will
  store, leaving out git's comment lines, the comment character the repository sets and the diff
  below the scissors line, or every line as written with `--as-is`. It refuses a message that names
  a tool rather than the work, or a bot as a co-author, and one that breaks a prose rule, read as
  Markdown, so a British spelling or a marker such as `TODO` fails while `Closes #12` passes. It
  names each rule once, at the first line that breaks it, and exits 0 on a pass, 1 on a refusal and
  2 when given no file.
- **Function.** `messageProblems`, `storedMessage`, `textToCheck` and `TOOLS` are exported with
  their types.
- **Docs.** The README says what the command checks and how a commit hook and a workflow run it.
- **Tests.** The cases of the command each repository kept as a script of its own pass against it,
  with a British spelling, a process artifact and an empty opener now refused, and CI runs the
  command from the packed tarball on the oldest Node.
